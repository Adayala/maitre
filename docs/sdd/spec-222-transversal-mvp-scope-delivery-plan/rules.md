# Reglas — SPEC-222

## Invariantes

1. MVP Demo y MVP Pilot son hitos diferentes.
2. El primer recorrido completo tiene prioridad sobre amplitud de features.
3. Datos reales no entran al ambiente gratuito de demo.
4. Single-branch UX no elimina aislamiento multi-tenant del modelo/tests.
5. Un módulo diferido no aparece como botón o promesa funcional.
6. Billing SaaS automatizado no bloquea validar entitlements.
7. Pago manual registrado no se presenta como procesamiento de pago.
8. Facturación fiscal real requiere I6 y controles ARCA aprobados.
9. Ningún incremento se acepta mediante edición manual de DB.
10. Cada slice termina desplegado, observable, testeado y recuperable.
11. Una ampliación de alcance explicita costo, trade-off y evidencia.
12. Specs completas fuera del MVP permanecen contratos futuros, no backlog inmediato.

## Regla de prioridad

Ante conflicto, se prioriza: seguridad/legalidad → integridad del recorrido → aprendizaje con usuario → confiabilidad → experiencia → optimización → expansión funcional.
